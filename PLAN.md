# Attendance Log - План разработки

## Технологический стек

- **Frontend**: Angular 22 (Standalone Components + Signals)
- **Backend/DB**: Firebase Firestore
- **Аутентификация**: Firebase Auth (email/пароль)
- **UI**: Angular Material

---

## Тема оформления (светлая/тёмная)

- **По умолчанию**: светлая тема.
- **Переключение**: глобальный переключатель (Header), доступный всем пользователям.
- **Хранение**: параметр сохраняется в `localStorage` (ключ например `theme`), читается при инициализации приложения.
- **Реализация**: `ThemeService` с Signal `isDark`. Angular Material поддерживает встроенные light/dark темы — переключается CSS-класс на `<body>` (`mat-app-background` + Material dark theme), состояние синхронизируется между страницами.
- **Независимо от аутентификации**: даже неавторизованный пользователь может переключать тему (это только локальное отображение).

---

## Права доступа (критично)

- **Неаутентифицированный пользователь** — только **чтение** (просмотр групп, студентов, дней и статусов посещаемости). Редактирование/добавление/удаление недоступно, элементы управления скрыты, клики по ячейкам заблокированы.
- **Аутентифицированный пользователь** — полный доступ: создание и редактирование групп/студентов, изменение статусов посещаемости.
- Каждое изменение статуса посещаемости фиксирует **два поля**: `modifiedBy` (кто) и `modifiedAt` (когда) и отображает их в UI.

## Модели данных (Firestore)

### 1. Student
```
students/{id}: {
  studentGroupId: string,  // ссылка на группу
  firstName: string,
  lastName: string,        // обязательно
  patronymic: string
}
```

### 2. StudentGroup
```
studentGroups/{id}: {
  name: string,            // обязательно
  studentIds: string[]     // массив ID студентов
}
```

### 3. ScheduleDay
```
scheduleDays/{id}: {
  studentGroupId: string,
  date: string,            // "YYYY-MM-DD"
  accounted: boolean,      // флаг "день учтён" (записей нет → false)
  transferred: boolean,    // флаг "перенесено в бумажный журнал"
  attendance: {
    [studentId]: {
      "8:30":  AttendanceEntry,
      "10:15": AttendanceEntry,
      "12:10": AttendanceEntry,
      "14:00": AttendanceEntry,
      "15:45": AttendanceEntry
    }
  }
}
```

### AttendanceEntry (статус посещения на одну пару)
```
{
  present: boolean,        // true = присутствует, false = отсутствует
  modifiedBy: string,      // email пользователя, изменившего статус (обязательно для записи)
  modifiedAt: Timestamp    // дата/время изменения (обязательно для записи)
}
```

### 4. MonthSettings (настройка "Суббота — учебный день")
```
monthSettings/{groupId}_{monthKey}: {
  saturdayIsStudyDay: boolean   // по умолчанию true
}
```
- `monthKey` = "`YYYY-MM`" (например `2026-09`); ID документа = `groupId_monthKey` (плоская коллекция).
- При создании группы создаётся **96 документов** (текущий месяц + следующие 95).
- Охватывает **ближайшие 8 лет**, горизонт фиксируется при создании.

## Логика флагов дня (`accounted`)
- **Всегда опираемся на флаг** `accounted`, а не на наличие записей для отображения рамки.
- **Автоматически**:
  - При добавлении **первой** записи в день → `accounted = true`.
  - При удалении/снятии записей → проверка списка `attendance`; если записей не осталось → `accounted = false`.
- **Вручную**: пользователь может отметить день кликом (см. HomeComponent) — флаг переключается напрямую.
- Флаг `transferred` переключается только вручную (кнопкой режима "Пометить перенесёнными в бумажный журнал").

## Компоненты

### 1. AuthComponent (login/register)
- Форма входа: email + пароль
- Кнопка "Регистрация" / "Вход"
- Редирект на главную после успешного входа

### 2. HomeComponent (главная страница, доступна всем без входа)
При заходе на сайт пользователь сразу попадает на главную страницу.

- **Header** (вверху по центру): селектор (Dropdown) с выбором группы
- **Для всех (в т.ч. неавторизованных)**:
  - Селектор группы
  - Кнопка **"Войти"** (→ на страницу входа)
- **Для авторизованных** (вместо кнопки "Войти"):
  - Кнопка **"Добавить группу"**
  - Кнопка **"Выйти"**
- Под селектором: навигация по месяцам `<` и `>` с отображением "Сентябрь 2026" и календарная сетка дней месяца, клик по дню → переход на страницу дня
- **По умолчанию** отображается **текущий месяц** (месяц, в котором находится пользователь, по системной дате).

**Визуальные состояния дней в календаре:**
- **Прошедший день** (не воскресенье):
  - **красная рамка**, если `accounted === false`;
  - **зелёная рамка**, если `accounted === true`.
- **Воскресенье**: **не кликабельно**, отображается **бледным** (приглушённым) и с **диагональными прочерками** (например, CSS-градиент для штриховки).
- **Будущий/текущий день** — без особой рамки, кликабельны (кроме воскресенья и субботы при выключенном чекбоксе "Суббота — учебный день").
- На каждом дне отображается **иконка бумажного листа** при `transferred === true` (индикация синхронизации электронного журнала с бумажным).

**Чекбокс "Суббота — учебный день"** (над календарём, по умолчанию **выбран**):
- Если выбран — все субботы месяца **активны** (кликабельны, отмечаются как учебные дни).
- Если снят — все субботы месяца обрабатываются **так же, как воскресенье**: бледные, некликабельны, с диагональными прочерками.
- **Данные о посещениях за субботу НЕ изменяются** при выборе/снятии чекбокса — это чисто визуальное переключение активности, чтобы случайное нажатие не удалило существующие записи.
- Настройка хранится **на группу и месяц**: при **создании группы** генерируются **96 записей** (8 лет × 12 месяцев, охватывающих текущий месяц + следующие 95) в отдельной коллекции. Значение по умолчанию — `true`.
- Горизонт **фиксируется при создании** (не сдвигается автоматически по мере истечения).
- Изменение чекбокса влияет только на отображаемый месяц выбранной группы.

**Над календарём — две кнопки режима:**
1. **"Пометить учтёнными"** — включает режим пометки. Тусклая — выкл, яркая/активная — вкл.
   - В режиме клик по любому **невоскресному** дню переключает его `accounted` (отмечает/снимает как учтённый, зелёный/красный).
2. **"Пометить перенесёнными в бумажный журнал"** — включает режим пометки. Тусклая — выкл, яркая — вкл.
   - В режиме клик по любому **невоскресному** дню переключает его флаг `transferred` (показывает/скрывает иконку бумажного листа).

**Правила режимов:**
- Режимы **не могут быть активны одновременно**: включение одного автоматически выключает другой.
- **Кнопка "Отметить все"** появляется только при активном режиме:
  - В режиме "учтёнными" — отмечает **все дни месяца** невоскресные дни флагом `accounted = true`.
  - В режиме "перенесёнными" — отмечает **все невоскресные дни месяца** флагом `transferred = true`.
- Оба режима включаются точечно (по одной кнопке) и доступны только авторизованным пользователям (изменение данных).
- В обычном (не в режиме пометки) клик по дню → переход на страницу дня.

> Примечание: выбор группы доступен и авторизованным, и гостям.

### 3. DayComponent (страница дня)
- **Заголовок**: "Посещаемость - [Группа] - [Дата]"
- **Таблица**:
  - Первая колонка: ФИО студентов (отсортированы по фамилии)
  - Первая строка: времена пар (8:30, 10:15, 12:10, 14:00, 15:45)
  - Ячейки: клик ставит галочку (✓ = присутствует, пусто = отсутствует)
- **Права доступа**:
  - Для всех: просмотр данных (read-only)
  - Для аутентифицированных: клик по ячейке изменяет статус, отображает `modifiedBy` и `modifiedAt` (например, в tooltip/иконке возле галочки)
  - Для неаутентифицированных: ячейки некликабельны, колонки с отметками скрыты
- **Кнопка "Назад"**: возврат на главную

### 4. GroupFormComponent (создание/редактирование группы)
- **Поле "Название группы"** (обязательное)
- **Список студентов**:
  - Каждый студент: поля [Фамилия*] [Имя] [Отчество]
  - Кнопка "Удалить" рядом с каждым
  - Кнопка "Добавить студента"
- **Кнопки "Сохранить" / "Отмена"**
- Валидация: название группы обязательно, фамилия каждого студента обязательна

## Маршрутизация

```
/login          → AuthComponent
/               → HomeComponent (доступен всем; редактирование зависит от аутентификации)
/group/new      → GroupFormComponent (только авторизованные)
/group/:id/edit → GroupFormComponent (только авторизованные)
/day/:groupId/:date → DayComponent (доступен всем; редактирование зависит от аутентификации)
```

## Сервисы

### 1. AuthService
- `login(email, password)` 
- `register(email, password)`
- `logout()`
- `user$` (Signal/ Observable текущего пользователя)

### 2. ThemeService
- `isDark` (Signal<boolean>) — текущее состояние темы
- `toggle()` — переключение темы
- Инициализация: чтение из `localStorage`, применение класса к `<body>`

### 2b. SettingsService
- `getSaturdayIsStudyDay(groupId, monthKey)` → Signal<boolean> — настройка для конкретной группы и месяца
- `setSaturdayIsStudyDay(groupId, monthKey, value)` — изменение настройки
- `generateMonthSettingsForGroup(groupId, startDate)` — при создании группы: создаёт **96** документов `monthSettings/{groupId}/{YYYY-MM}` (текущий месяц + следующие 95), `saturdayIsStudyDay = true`

### 2. StudentGroupService
- `getGroups()` → Signal<StudentGroup[]>
- `getGroup(id)` → Signal<StudentGroup>
- `createGroup(group)`
- `updateGroup(id, group)`
- `deleteGroup(id)`

### 3. StudentService
- `getStudentsByGroup(groupId)` → Signal<Student[]>
- `createStudent(student)`
- `updateStudent(id, student)`
- `deleteStudent(id)`

### 4. ScheduleDayService
- `getScheduleDay(groupId, date)` → Signal<ScheduleDay>
- `getScheduleDaysForMonth(groupId, month)` → Signal<ScheduleDay[]> (для отображения состояний календаря)
- `createOrUpdateScheduleDay(groupId, date, attendance)`
- `toggleAttendance(groupId, date, studentId, timeSlot)` — при изменении задаёт `present`, `modifiedBy` (email текущего пользователя), `modifiedAt` (serverTimestamp); **автоматически синхронизирует флаг `accounted`**: при добавлении первой записи → `accounted = true`, при удалении последней → `accounted = false`
- `toggleAccounted(groupId, date)` — ручное переключение флага `accounted`
- `toggleTransferred(groupId, date)` — переключение флага `transferred` (иконка бумажного листа)
- `markAllGrouped(groupId, month, flagType)` — установка флага (`accounted` или `transferred`) = true для всех невоскресных дней месяца

## Шаги реализации

### Фаза 1: Инициализация проекта
1. Создать Angular проект: `ng new attendance-log`
2. Добавить Angular Material: `ng add @angular/material`
3. Настроить Firebase: `ng add @angular/fire`
4. Создать конфигурацию Firebase

### Фаза 2: Аутентификация
1. Создать AuthService
2. Создать AuthComponent (логин/регистрация)
3. Логика видимости кнопок "Войти"/"Выйти"/"Добавить группу" в Header в зависимости от состояния аутентификации (простой guard для маршрутов создания/редактирования группы)

### Фаза 3: Группы и студенты
1. Создать модели данных
2. Создать StudentGroupService и StudentService
3. Создать HomeComponent (селектор группы, календарь)
4. Создать GroupFormComponent
5. При создании группы вызывать `SettingsService.generateMonthSettingsForGroup(groupId)` (96 записей `monthSettings` на 8 лет)

### Фаза 4: Посещаемость
1. Создать ScheduleDayService
2. Создать DayComponent с таблицей
3. Реализовать логику переключения посещаемости с автобновлением флага `accounted`

### Фаза 5: Флаги дней и режимы пометки
1. Кнопки "Пометить учтёнными" и "Пометить перенесёнными в бумажный журнал" (взаимоисключающие режимы + кнопка "Отметить все" в активном режиме)
2. Визуальные состояния календаря (красный/зелёный, воскресенья, иконка бумажного листа)
3. Чекбокс "Суббота — учебный день" (без изменения данных о посещениях)
4. Реализовать `toggleAccounted`, `toggleTransferred`, `markAll` + синхронизацию `accounted`

### Фаза 6: Финализация
1. Обработка ошибок
2. Пустые состояния
3. Тестирование
